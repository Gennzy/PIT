# ПИТ v5 — серверная платформа для нескольких СТО

Это исходники работающего приложения, а не статическая HTML-демонстрация. Для записи, доступа и данных нужен запущенный сервер. Двойной клик по `index.html` не запускает систему.

## Что сделано

- Отдельная админка владельца для компьютера: обзор, настройки, прайс, часы и дни работы, посты, функции, камеры, сотрудники, клиенты, несколько СТО, аудит и экспорт.
- Общий сервер Node.js 24+ и постоянная SQLite-база. Все приватные запросы проверяют СТО и права пользователя. Клиент видит свои машины и заказы; мастер — рабочие данные своего СТО; владелец — настройки своего СТО.
- Нет общего демо-PIN и фиктивного «входа»: email/пароль, хеширование scrypt, HttpOnly/SameSite cookies, отзыв сессий при смене пароля, проверка Origin, ограничения попыток входа.
- Запись на реальное свободное время с учётом длительности и числа постов. Сервер считает цену, фиксирует прайс в заказе и не допускает двойной записи на один пост. Перенос и отмена сохраняются.
- Приёмка, состояния работ, реальные фотографии находок, согласование/отказ клиента, дополнительная цена, чат, завершение заказа, уведомление о готовности.
- При согласовании дополнительных работ сервер резервирует дополнительное время. Если оно пересекается с следующей записью, операция отклоняется: мастер должен договориться о другом окне, а не скрытно задержать следующего клиента.
- Напоминание за 2 часа и сообщения об освобождённых более ранних окнах — в уведомлениях приложения. Перенос на такое окно делает клиент сам; это не автоматическая перебронь.
- Гараж с фактическим годом, номером, пробегом, двигателем и параметрами. Каталог: 202 модели/поколения, включая старые машины. Есть ручной ввод любой другой модели.
- Склад шин: 60 ячеек, приём, выдача, поиск по номеру, сезон и оплаченный срок. Информация о комплекте видна его клиенту.
- История только завершённых заказов. Настоящий QR-код, публичная ссылка на 30 дней и отзыв ссылок. Телефон, госномер и чат в публичную историю не попадают.
- Рабочие кнопки календаря (ICS), маршрута, звонка, обмена ссылкой. PWA-манифест и service worker без кэширования приватных API/заказов/страниц владельца.
- 20 автоматических API-проверок; браузером проверены регистрация, настройка СТО, добавление старого автомобиля, запись и чат.

## Честные ограничения: без имитации успеха

В старой версии камера была картинкой, скан номера и распознавание лампы — таймерами, а «push отправлен» — текстом. В этой версии такого нет.

- **Камеры**: владелец задаёт реальную HTTP(S)-ссылку на поток. В приложении используется браузерный video-плеер и ссылка на камеру. Камера и совместимый поток нужны отдельно. RTSP напрямую не работает; нужен видеошлюз. Нативный HLS поддерживается не во всех браузерах. Прямой поток должен иметь собственную защиту доступа; сервер не является прокси видеосервера. Не используйте URL с паролями.
- **Автоскан госномера**: OCR не подключён; функция принудительно отключена. Вместо поддельного скана работает реальный поиск по номеру в очереди и складе.
- **Лампы**: работает справочник с ручным выбором. Автоматического распознавания фото нет. Это не диагноз и не разрешение продолжать движение; приоритет у руководства машины и специалиста.
- **Голос**: реальный SpeechRecognition, когда его поддерживает браузер и пользователь разрешил микрофон. При отсутствии поддержки — ручной ввод. Распознавание может использовать внешнюю службу браузера; офлайн-приватность не обещается.
- **Уведомления**: сохраняются в приложении. Внешние Web Push, SMS, Telegram, доставка почты и проверка телефона по SMS не подключены. Напоминания создаются, пока сервер работает. Фоновую доставку на закрытый телефон не обещаем.
- **Фото автомобилей**: сохранены изображения из исходного архива для 15 моделей. Для остальных показывается текстовая карточка, а не фотография похожой машины. Технические параметры и нормы обслуживания не выдумываются — вводятся по конкретному автомобилю.
- **Коммерция**: архитектура для нескольких клиентов есть. Подписки, лицензирование, онлайн-оплаты, касса, биллинг, 2FA и автоматическое восстановление пароля по email не реализованы. Суммы завершённых заказов — не доказательство получения оплаты.

## Запуск на компьютере

Понадобится **Node.js 24 или новее**. Внешних npm-зависимостей нет: QR-модуль включён в исходники. `npm install` не требуется.

1. Распакуйте архив и откройте терминал в папке `pit-v5`.
2. Скопируйте `.env.example` в `.env`.
3. В `.env` задайте email и надёжный пароль владельца (минимум 10 символов), код и название первого СТО.
4. Запустите:

```sh
node --env-file=.env server/server.js
```

5. Откройте в браузере:
   - приложение: `http://localhost:3000/app/first-sto`
   - админку: `http://localhost:3000/admin/first-sto`

Если изменили `STO_SLUG`, замените `first-sto` в адресах. Владелец создаётся только на пустой базе. Последующая правка OWNER_PASSWORD в `.env` **не меняет** пароль уже созданной учётной записи — используйте профиль или сброс пароля сотрудника через админку.

Аккаунт клиента можно зарегистрировать на странице приложения. Мастера создаёт владелец в разделе «Команда и клиенты». Владелец тоже может пользоваться рабочим местом мастера. Один браузер хранит одну активную сессию; для параллельной проверки клиента и мастера используйте разные профили браузера или приватное окно.

## Несколько СТО одного владельца

Раздел «Мои сервисы» → «Добавить СТО». Создаётся отдельный сервис с чистыми данными. Для нового СТО копируются email и текущий пароль владельца, но не клиентские данные. Аккаунты владельца в разных СТО независимы; последующее изменение пароля одного не обновляет остальные. После перехода нужно войти в выбранный сервис.

## Независимый покупатель с отдельным владельцем

На вашем сервере после первого запуска создайте отдельного владельца командой provision. Она доступна только оператору сервера, не обычному пользователю приложения. Укажите переменные окружения NEW_STO_SLUG, NEW_STO_NAME, NEW_OWNER_EMAIL, NEW_OWNER_PASSWORD, затем выполните:

```sh
node --env-file=.env --env-file=customer.env server/provision.js
```

`customer.env` заполните по `customer.env.example`, держите приватно и удалите после создания. Новый владелец не видит сервисы других владельцев. Учётные записи пользователей из разных СТО не смешиваются даже при совпадающем email.

## Развёртывание на сервере

В комплекте Dockerfile, compose.yaml и пример Caddyfile.

- Настройте домен, HTTPS и постоянный том для `/app/data`.
- Установите `PUBLIC_ORIGIN=https://ваш-домен`, `COOKIE_SECURE=true`, `HOST=0.0.0.0`.
- За обратным прокси не открывайте порт приложения напрямую в интернет. Compose публикует его на 127.0.0.1.
- QR-код версии 5-L поддерживает URL до 106 UTF-8 байт; используйте короткий домен. QR локальный, не отправляет историю во внешний QR-сервис.
- `TZ=Europe/Moscow` задаёт единый часовой пояс развёртывания. Эта версия предназначена для СТО одного часового пояса; даты в браузере должны соответствовать ему. Мультизональные расписания пока не реализованы.
- Для установки PWA, микрофона и камеры требуется безопасный контекст HTTPS или localhost.
- Все изменения требуют сети. В офлайн-режиме нет фиктивной успешной записи и очереди несохранённых действий.

```sh
docker compose up --build -d
```

Перед продажей реальным СТО обязательны проверка на вашем хостинге, настройка резервного копирования, мониторинга, политики хранения/удаления персональных данных, согласий на публичную историю и независимый аудит безопасности. Испытания не заменяют эксплуатационное внедрение.

## База и резервная копия

По умолчанию: `data/pit.sqlite`; SQLite WAL. Папка содержит персональные данные и фотографии. Не публикуйте её, не добавляйте в git или архив для клиентов. Ограничьте доступ на уровне ОС. Эта версия рассчитана на один серверный процесс с локальной постоянной файловой системой, не на сетевой диск или несколько реплик.

Для простой безопасной резервной копии остановите сервер и скопируйте **всю папку data**, включая возможные файлы `-wal` и `-shm`. Возобновите сервер. Не копируйте только активный `pit.sqlite` во время работы. Для онлайн-резервирования используйте SQLite Backup API или VACUUM INTO через отдельный инструмент. Экспорт из админки — читаемый экспорт данных, не автоматическая восстановительная резервная копия.

## Проверки

```sh
npm test
```

Тесты создают временную базу и сервер на отдельном порту, затем удаляют её. Реальные данные не меняются. Проверяется: доступ по ролям, изоляция СТО, двойная запись, фиксация цены, согласование, работы, чат, склад, QR/отзыв ссылок, экспорт без паролей, смена пароля и CSRF.

## Структура

- `server/server.js` — HTTP/API, права, SQLite, расписание и уведомления.
- `server/catalog.json` — каталог; диапазоны лет ориентировочные для выбора поколения, ручной ввод доступен.
- `server/qr.js` — локальный QR Model 2 v5-L (декодирование проверено).
- `server/provision.js` — создание независимого покупателя.
- `pit/admin.html`, `pit/admin.js` — отдельная админка.
- `pit/index.html`, `pit/app.js` — мобильное приложение и рабочее место мастера.
- `pit/shared.js`, `pit/ui.css` — общие функции и оформление.
- `pit/history.html` — публичная история по ограниченной ссылке.
- `tests/api.test.js` — проверяемые серверные сценарии.

Исходные изображения и шрифты перенесены из предоставленного архива; права на их коммерческое использование нужно проверить перед продажей.
